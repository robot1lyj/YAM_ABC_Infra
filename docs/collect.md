# 数据采集与 Leader 双按钮手册

适用：2 台官方 YAM Leader、2 台标准平行夹爪 Follower、3 台 D405。采集模式 `collect` 由人示范，不需要 Thor 模型；与 HIL 运行中的人工纠正分开。

## 四种模式的两个按钮

左右 Leader 的按钮都控制整套双臂；不分别接管单臂。这里“顶部/第二”对应 SDK 的 `[top, second]` 顺序，首次实物联调先低速确认位置。启动设备时保持按钮释放。

| 模式 | 顶部按钮单击 | 第二按钮 |
|---|---|---|
| 遥操作 | 保持时启动；已运行时不重复启动 | 保持 |
| 推理 | 保持时启动/恢复；已运行时不重复启动 | 保持 |
| HIL | 保持时启动/恢复；运行中人工接管/交还 | 保持 |
| 数据采集 | 保持时启动遥操作；人工运行中开关一段录制 | 保持，当前片段标为 aborted |

- 第二按钮优先。任意一侧按住期间，顶部按钮、键盘和网页的启动/模式切换都不能恢复运行，并清空待处理命令。
- 松开第二按钮不会自动恢复。必须重新按顶部按钮或 `s`；若顶部已按住，要先松开再按。
- 顶部使用上升沿、整站250ms去抖；两侧同一时刻按下只触发一次。左侧一直按住不屏蔽右侧后续独立按下。
- 首次读到已按住的顶部按钮不会启动。没有双击、长按、组合键切模式或退出功能。
- 保持时 Follower 保持，Leader 进入人工/重力补偿；不是四臂机械锁死。软件保持不是硬件急停，退出也不是保持。

## 先用模拟练习

```bash
.venv/bin/python -m yam_abc_reproduce.hil.run --mock --mode collect --web-port 8766
```

打开本机 `http://127.0.0.1:8766`：

1. 选择数据采集模式，点击“开始 / 恢复”（键盘 `s`），状态应为 `human`。
2. 摆好物体，点击“开始 / 结束一段采集”（`r`），确认 `recording: true`。
3. 用 Leader 示范。真实设备需要先对齐姿态，夹爪有软接管保护；不要强拉处于策略镜像中的 Leader。
4. 结束前点击成功/失败（`g` / `f`），再按 `r` 结束本段。默认结果是 `unknown`，不会自动判断任务成功。
5. 确认 `recording: false`，重置场景，再按 `r` 开始下一段。新段结果重置为 `unknown`。
6. 需要暂停运动时按第二按钮或空格；正在采集的段会标为 `aborted`。重新启动后要再次明确开始录制。
7. 所有示范结束后先结束录制、支撑机械臂，再退出 `q`；等待视频封装和会话索引写完。未明确结束的活动采集片段在退出时标为 `aborted`。

第一次顶部按钮从 HOLD 启动遥操作，**不会同时开始录制**。后续顶部按钮只开关录制，结束录制仍处于遥操作，便于准备下一次示范。相机未组成有效观测时不会开始一段，检查界面 `recording` 状态。

真机命令去掉 `--mock`；先按 [硬件手册](workstation.md) 填写夹爪电机型号、CAN 与 D405 序列号。构造设备可能施加力矩并校准夹爪，不要把启动命令当作只读检查。

## 记录与导出

```text
会话目录/
  session.json
  episode_000001/steps.jsonl, top.mp4, left.mp4, right.mp4, manifest.json
  episode_000002/...
```

采集开始前、两段之间不保存帧。活动片段保留观测缺失等质量信息，导出器只选择完整、连续人工段；不能把有缺口的轨迹硬拼起来。采集记录 `source=human`、`is_intervention=false`，与 HIL 干预标签区分。

模式切换先保持、关闭旧片段；进入遥操作/推理/HIL后连续记录，进入采集后等待录制操作。会话队列32项、单段编码队列8帧，任何写盘错误或队列满都会报告故障，不能无限堆内存。

按 [格式转换手册](convert.md) 对单个 `episode_XXXXXX` 运行专家导出。`aborted` 默认拒绝导出；成功/失败是人工标记，失败段是否进入训练由数据审核决定。尚未实现手柄删除片段、任务成功自动判断或自动上传训练。

旧英文采集说明见 [历史归档](archive/collect-1c04c83.md)，只用于兼容旧工具。
