# 数据集清洗与转换工作台

独立于采集工作台运行，不构造机械臂、不连接相机、不自动转换采集中的数据。

```bash
uv run --no-sync python -m yam_abc_reproduce.dataset_workbench.web --port 8767
```

打开 [数据集工作台](http://127.0.0.1:8767/)。使用项目现有环境；首次安装依赖见 [环境手册](environment.md)。
采集界面仍在 8766。建议采集机只录制，上传/挂载到服务器后，在服务器运行本工作台；本工具不自动上传。

桌面采用固定一屏布局：紧凑顶部统计、左右列表与三路预览、底部任务条。整页不滚动，长列表和报告局部滚动；全部任务可从底栏“全部”查看。

## 导入与索引

“导入数据”填写**运行工作台的机器**上的绝对路径，支持单集、会话、包含多个会话的目录和已挂载共享目录。
递归识别 `yam_hil_v1` / `yam_hil_v2` 的 `manifest.json`，跳过正在录制的集、隐藏目录和 exports。
同一路径重复导入不增重；未变化的指纹跳过更新。原始指纹包含清单及主要数据文件的大小/mtime；LeRobot按info与episode元数据文件更新。快速指纹不替代完整哈希，也不保证检出保留大小/mtime的改写。
目录库分配持久ID，路径与episode键单独存储。通过迁移包恢复保留ID并重定位根目录；直接手工移动后重新扫描不会自动继承旧ID，请使用下面的迁移流程。
深度检查可识别本次所选集中的完整文件内容重复，不自动删除副本。

索引默认存入 `data/dataset_workbench/catalog.sqlite3`，包含集合、分类、备注、回收站、检查摘要、任务和操作审计。
任务完整报告独立保存在同目录 jobs 下，页面轮询只获取摘要。`--catalog` 可指定其他目录。
备份整理结果时，在关闭工作台后备份该目录；还需单独保留原始录制。索引不是视频备份。

支持导入 **LeRobot v3.0 的 MP4 video 数据**：分批读取meta/episodes，正确定位共享Parquet文件及视频时间范围。嵌入式图片和其他版本明确拒绝。列表和详情显示格式标识，模拟标记独立显示；格式筛选不触发视频读取。LeRobot当前支持浏览、检查、分类、集合和迁移；不支持成品重合并或子集物理导出。原始转换仍面向本项目14维双臂数据。

## 整理和逐集审阅

- 点击一行：三路图像、中文任务名、英文 task、时长、来源与检查结果；拖动进度条，松开后读取选定帧。
- 勾选：支持跨页保留选择；每页 100 集。搜索匹配中文任务、英文task和备注。列表一次返回100条摘要，使用游标翻页，不返回全部清单；筛选不在每页强制统计精确总数。切换分类/集合会清空选择。
- “分类 / 整理”：标记成功、失败、待审核，加入集合，从当前集合移出，移入回收站或恢复。
- 标记失败后自动出现在“失败数据集”。这是可导出的逻辑分类，源文件不搬动，原始 outcome 不改写。
- “＋”创建中文集合，可把不同目录中的集加入同一集合，即逻辑合并；一集可属于多个集合。
- 新增某集：导入其目录后加入目标集合；移除某集：从集合移出或放入回收站。没有永久擦除原文件按钮。
- 逐集备注记录失败原因或人工复核结果。审核分类和源采集结果独立，导出清单保留两者。

预览按需取帧，不连续播放；v2 先定位物理分段，再读取段内数据，不从一小时任务开头逐行扫描。
HDF5预览直接切片读取目标video_indices；视频从邻近关键帧定位，缩略图上限960×540。应用缓存上限32 MiB，最多2个同时解码；拖动时取消旧的前端请求，已经进入后端的解码不强制中止。没有D405一小时RK3588负载验收。

## 检查和清洗

快速检查：媒体能打开、视频帧数、manifest/实际行数、空集、14 维状态/动作及有限值、视频索引、观测有效性、时间戳单调性、tick 连续性与来源状态。
快速检查不完整解码视频；头部缺帧数时采用已提交清单中的声明帧数，无声明则提示深检。声明数量不能证明完整视频无损。数值检查仍逐批扫描所选集，因此长任务检查耗时随数据量增加。LeRobot快速检查扫描相关Parquet行组并检查媒体范围；深检解码该集的视频时间范围。

深度检查：额外完整解码三路视频，计算 MP4/HDF5/JSONL 内容指纹，任务详情列出原始数据本次选择的完全重复对；LeRobot检查目前不做内容去重。逐集报告流式写JSONL，可从任务详情下载。
它不判断任务语义成功、曝光质量、机械臂碰撞或视觉近似重复；没有自动修复/删除按钮。
启动无图像帧或采集中已有无效观测也会列为异常，需人工判断，不能把“异常”直接等同数据完全不可用。

实际清洗通过检查 → 人工预览 → 备注/分类 → 移出坏集 → 选择合格集合导出完成。
HIL 可勾选“仅提取人工专家片段”；帧级任意裁剪、自动去静止、模糊检测暂未实现。
损坏录制恢复仍使用 [转换手册](convert.md) 的独立恢复命令，恢复集默认不从此界面直接进入训练导出。

## 合并与转换

勾选原始集，点“转换”，填写**新的独立输出目录**。转换输入是完整HDF5/JSONL＋MP4＋清单，混选或仅选LeRobot会拒绝执行。
输出为一个 LeRobot **v3.0** 数据集，官方读取器兼容基线 **0.5.1**。
支持不同英文 task，分别写 tasks.parquet、逐帧 task_index 和逐集 tasks；统一重建 episode/global index 和统计。
帧率与三路分辨率需一致，否则失败提示；不自动重采样或缩放。失败集只在明确选中时参与导出。

完整连续视频且帧索引/数量完全匹配时，重新封装 MP4，不重编码；专家筛选和缺口分组需要解码重编码。
统计计算仍需解码图像；SHA-256 仍需读完整来源，因此已有 MP4 不代表转换完全不耗 CPU/磁盘。
读取与 Parquet 写入沿用有界分批；不把整集图像存入内存。输出失败保留 `.partial/failure.json`，重试使用新目录。
不覆盖旧输出；仅成功完成后将 .partial 原子改名。`curation.json` 保留源路径、清单、文件指纹、审核、备注与输出集映射。

独立spawn工作进程，单后台worker，最多4个运行/排队任务，不与采集进程共享控制循环；但同机同时处理仍会竞争 CPU/磁盘。
任务完成/失败持久化，进程异常退出后旧运行任务标为中断；不自动续跑，也没有强制中途取消功能。
索引/集合可汇集多个会话；暂不包含多用户权限、云对象存储、分布式转换和训练集版本发布。

无界面服务器仍可使用 [一键离线脚本](convert.md)，它与此界面都由用户主动触发。

## 后端优化方案与实施进度：约100 GB / 目标100小时

### 状态与范围

2026-09-11 用户明确要求专业化记录上一轮方案，后续再实施。本节最初是已确认待实施方向；用户随后授权双格式、低资源与迁移改造。**已完成范围见本文现行说明，以下整体路线不代表全部实施。**当前数据量约 **100 GB**，来自用户说明，未扫描磁盘实测；GB/GiB口径、episode数量、文件数量、存储介质和并发用户数尚未核验。

目前不因100 GB容量直接引入分布式系统或迁移数据库。容量不能单独决定目录查询负担；实施前补测episode/文件数量、冷启动时间、查询时延、随机预览与峰值内存。最新本次已实施摘要索引/游标分页/缓存/工作进程和迁移能力；只使用模拟数据测试，未完整处理用户约100 GB来源。

### 目标架构与职责

1. 原始采集继续MP4＋HDF5＋JSON清单，采集链路不自动转换。
2. SQLite目录服务管理数据源、episode、文件位置、审核、集合、版本与任务；视频和逐帧数值保存在数据文件中。
3. 管理界面只查询目录摘要，按需加载详情/预览；长任务独立后台执行并限制资源。
4. 用户发布训练版本时冻结成员及来源，在服务器转换为LeRobot v3.0聚合分片。逻辑episode与物理文件边界分离。
5. Lance作为服务器训练读取的候选对比实验，先评估condapi兼容性、吞吐、CPU/内存和存储成本，不替换当前采集格式。

### 第一阶段：目录查询与索引（优先）

- 将任务ID、中文名称、英文task、时间、帧数、时长、审核、检查状态从完整JSON提取为可查询列；按实际过滤/排序建立复合索引。
- 一次分页查询返回摘要，取消当前逐集get的多次查询；详情按ID另取，不向列表传输完整manifest或检查明细。
- OFFSET分页改为稳定排序键＋ID的游标分页；分类计数增量维护或缓存，不逐次全表统计。
- 搜索只覆盖必要字段；中文分词/子串索引策略需单独验证，不假设普通索引能加速任意包含查询。
- 开启SQLite WAL并控制批量事务长度；数据库保存在服务本地磁盘，浏览器通过API访问，不把WAL数据库放在共享网络盘上多机直接打开。
- 增加稳定episode身份，将数据源/相对路径与身份分开；优先采用原始episode_id，旧格式建立持久映射；冲突和多个副本显式处理，不凭同名文件合并。
- 索引模型覆盖数据源、episode、文件/分片、episode位置、集合/版本、检查/任务。未来并发写入成为实测瓶颈后再考虑PostgreSQL。

### 第二阶段：增量导入与低资源预览

- 首次扫描只读必要清单/元数据，分批入库、限频报告进度，发现一批即可浏览；不自动完整解码或计算全部视频SHA-256。
- 再次扫描用文件大小、mtime和清单版本发现变化；这些是快速变化检测，不等于内容完整性校验。深度校验独立执行，按文件版本复用结果。
- 来源离线仍可浏览目录与已有缩略图；标明离线，不把无法访问当作文件已删除。
- YAM与LeRobot提供独立读取适配器；LeRobot导入分批读取meta/episodes，建立episode到Parquet行范围及MP4时间范围的映射，不加载整个训练Dataset对象。
- HDF5通过定位切片取所需行；MP4跳到邻近关键帧再解码到目标帧，验证帧号/时间戳映射，避免每次从段首解码。
- 缩略图/预览缓存以来源版本、相机和帧为键，设磁盘及内存上限并淘汰；优先服务最新预览请求，抑制快速拖动产生的过时工作。

### 第三阶段：版本发布与聚合转换

- 集合合并、失败分类、移出某集仅修改目录；发布时冻结成员、审核、来源指纹、转换参数和训练划分，生成不可变版本。
- 原始审核后续变化不改写已发布版本。训练/验证按来源episode或会话分组，避免同一长任务的相邻片段跨划分。
- 多个短集聚合到目标大小的Parquet/MP4分片，正确更新episode/global/task索引、统计和文件偏移。
- 长任务保持逻辑身份，物理布局服从锁定读取器支持范围；不为满足固定文件大小盲目切断逻辑任务。
- 分片大小可配置，以随机读取、文件数、重试成本实测选择。兼容MP4优先重新封装，不保证任意视频无需重编码。
- 按批流式写元数据、检查报告及来源清单，不在内存积累全部集的完整记录。
- 后台重任务改为独立进程、有界队列，持久化转换单元检查点，复用验证通过的产物；完成校验后原子发布，失败不暴露为完整训练版本。

### 验收计划（待执行）

- 索引用1万、10万集模拟记录测试首次打开、筛选、搜索和深分页；模拟规模不代表当前用户实际集数。
- 核验列表请求不读取MP4/HDF5，内存不随视频总容量线性增长；分别记录冷/热缓存时延与峰值内存，不提前承诺毫秒指标。
- 使用真实长集验证首帧、末尾跳转、三路同时预览和数据定位正确性。
- 记录后台导入/检查/转换期间的界面响应、CPU、内存、磁盘吞吐；约100 GB来源的实测需后续明确执行。
- RK3588验证轻量浏览，服务器验证重检查与转换；独立进程仍可能与采集竞争同机CPU/磁盘。

## 打包迁移与独立部署（已实现）

1. 勾选需要迁移的集，点“打包迁移”，填写新的`.tar`路径。原始集带完整原始目录；LeRobot带完整来源目录，因为多个episode可能共用分片。包内审核索引只包含所选集，包含备注、回收站状态及相关集合关系。
2. 后台顺序读取文件、同步计算SHA-256，不压缩MP4；文件清单写SQLite，TAR成员索引不全量累积在内存。打包前结束录制/源文件修改，过程中检测到文件变化会失败。
3. 自行复制迁移包到目标机器。本工具不自动上传。源数据、迁移包、解包后的数据会分别占空间；TAR大小约等于携带数据大小，需要预留目标空间。
4. 目标机器启动工作台，点“恢复迁移包”，填写包路径和新的数据目录。逐文件校验后发布恢复目录，再恢复ID、标签、备注与集合。所有活动文件定位由新根目录加包内相对路径重建；历史清单中的原机器路径可能作为来源说明保留，不用于访问数据。
5. 同目录库恢复相同ID/版本会重定位已选集；版本冲突明确失败，不悄悄覆盖不同版本。未选择的旧集不变。恢复文件验证完成而目录库合并失败时保留已验证文件供检查，不自动擦除。

输出不覆盖已有文件/目录。失败保留`.partial`供排查，重试使用新目标；尚未提供分卷、断点续传或自动清理。普通文件受支持，符号链接、越界路径、不受支持的TAR成员类型拒绝。完整SHA-256用于检测内容损坏，不是来源签名认证。

跨机器不必安装机械臂SDK/Torch：复制或克隆项目代码后执行独立锁定入口：

```bash
uv run --locked --script scripts/dataset_workbench.py --port 8767 --catalog /data/yam_catalog
```

依赖见scripts/dataset_workbench.py及其.lock；这不是复制旧.venv。配置路径由参数指定，代码路径从脚本所在仓库解析，不固化/home/wuyan-lyj。默认仅监听localhost；远程浏览通过SSH端口转发或由管理员配置代理，文件路径始终属于运行服务的机器。
