# 数据集清洗与转换工作台

独立于采集工作台运行，不构造机械臂、不连接相机、不自动转换采集中的数据。

```bash
uv run --no-sync python -m yam_abc_reproduce.dataset_workbench.web --port 8767
```

打开 [数据集工作台](http://127.0.0.1:8767/)。使用项目现有环境；首次安装依赖见 [环境手册](environment.md)。
采集界面仍在 8766。建议采集机只录制，上传/挂载到服务器后，在服务器运行本工作台；本工具不自动上传。

桌面采用固定一屏布局：紧凑顶部统计、左右列表与三路预览、底部任务条。整页不滚动，长列表和报告局部滚动；全部任务可从底栏“全部”查看。

## 导入与索引

“导入数据”填写**运行工作台的机器**上的绝对路径，支持单集、会话、包含多个会话的目录和已挂载共享目录。
递归识别 `yam_hil_v1` / `yam_hil_v2` 的 `manifest.json`，跳过正在录制的集、隐藏目录和 exports。
同一路径重复导入更新清单，不产生重复索引；原清单变化会清空过期检查结果。
来源路径是本地索引身份，移动目录需重新导入；目前不自动迁移旧身份或合并不同路径副本。
深度检查可识别本次所选集中的完整文件内容重复，不自动删除副本。

索引默认存入 `data/dataset_workbench/catalog.sqlite3`，包含集合、分类、备注、回收站、检查摘要、任务和操作审计。
任务完整报告独立保存在同目录 jobs 下，页面轮询只获取摘要。`--catalog` 可指定其他目录。
备份整理结果时，在关闭工作台后备份该目录；还需单独保留原始录制。索引不是视频备份。

首版**不导入已转换的 LeRobot 数据集**，遇到其 meta/info.json 会列出跳过原因。
当前面向本项目双臂 14 维状态/动作与 top/left/right 三路 RGB 数据；不声称是任意机器人格式转换器。

## 整理和逐集审阅

- 点击一行：三路图像、中文任务名、英文 task、时长、来源与检查结果；拖动进度条，松开后读取选定帧。
- 勾选：支持跨页保留选择；每页 100 集。搜索匹配任务、路径和备注。切换分类/集合会清空选择。
- “分类 / 整理”：标记成功、失败、待审核，加入集合，从当前集合移出，移入回收站或恢复。
- 标记失败后自动出现在“失败数据集”。这是可导出的逻辑分类，源文件不搬动，原始 outcome 不改写。
- “＋”创建中文集合，可把不同目录中的集加入同一集合，即逻辑合并；一集可属于多个集合。
- 新增某集：导入其目录后加入目标集合；移除某集：从集合移出或放入回收站。没有永久擦除原文件按钮。
- 逐集备注记录失败原因或人工复核结果。审核分类和源采集结果独立，导出清单保留两者。

预览按需取帧，不连续播放；v2 先定位物理分段，再读取段内数据，不从一小时任务开头逐行扫描。
视频解码最多到目标段内的选定帧，缩略图上限 960×540。没有真实一小时 RK3588 负载验收。

## 检查和清洗

快速检查：媒体能打开、视频帧数、manifest/实际行数、空集、14 维状态/动作及有限值、视频索引、观测有效性、时间戳单调性、tick 连续性与来源状态。
部分 MP4 头部不提供帧数，快速检查也会退回解码计数，因此“快速”不承诺固定耗时。

深度检查：额外完整解码三路视频，计算 MP4/HDF5/JSONL 内容指纹，任务详情列出本次选择的完全重复组。
它不判断任务语义成功、曝光质量、机械臂碰撞或视觉近似重复；没有自动修复/删除按钮。
启动无图像帧或采集中已有无效观测也会列为异常，需人工判断，不能把“异常”直接等同数据完全不可用。

实际清洗通过检查 → 人工预览 → 备注/分类 → 移出坏集 → 选择合格集合导出完成。
HIL 可勾选“仅提取人工专家片段”；帧级任意裁剪、自动去静止、模糊检测暂未实现。
损坏录制恢复仍使用 [转换手册](convert.md) 的独立恢复命令，恢复集默认不从此界面直接进入训练导出。

## 合并与转换

在任意分类或集合勾选集，点“合并 / 转换”，填写**新的独立输出目录**。
输出为一个 LeRobot **v3.0** 数据集，官方读取器兼容基线 **0.5.1**。
支持不同英文 task，分别写 tasks.parquet、逐帧 task_index 和逐集 tasks；统一重建 episode/global index 和统计。
帧率与三路分辨率需一致，否则失败提示；不自动重采样或缩放。失败集只在明确选中时参与导出。

完整连续视频且帧索引/数量完全匹配时，重新封装 MP4，不重编码；专家筛选和缺口分组需要解码重编码。
统计计算仍需解码图像；SHA-256 仍需读完整来源，因此已有 MP4 不代表转换完全不耗 CPU/磁盘。
读取与 Parquet 写入沿用有界分批；不把整集图像存入内存。输出失败保留 `.partial/failure.json`，重试使用新目录。
不覆盖旧输出；仅成功完成后将 .partial 原子改名。`curation.json` 保留源路径、清单、文件指纹、审核、备注与输出集映射。

单后台 worker，最多 4 个运行/排队任务，不与采集进程共享控制循环；但同机同时处理仍会竞争 CPU/磁盘。
任务完成/失败持久化，进程异常退出后旧运行任务标为中断；不自动续跑，也没有强制中途取消功能。
索引/集合可汇集多个会话；暂不包含多用户权限、云对象存储、分布式转换和训练集版本发布。

无界面服务器仍可使用 [一键离线脚本](convert.md)，它与此界面都由用户主动触发。
