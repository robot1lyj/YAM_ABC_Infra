## 2026-09-14：硬件到齐后的架构固定

**当前追加约束**：用户已确认P0及接线完成。后续按产品级交付推进：完整可靠且不过度防御；以使用者为中心持续维护设备与采集平台（含初始化、调试和维护）、数据集平台，并按实际场景扩展；记忆必须分层、热入口有内容预算、低频细节降为冷资料。设计评审与两平台验收归 [产品交付原则](dagger_architecture.md#产品交付原则2026-09-14)，用户追加两平台均需开放局域网端口、跨平台浏览器使用；日常设备操作和结果记录经界面，具体交付要求归同一架构owner。具体字节预算与降级方法归 [记忆维护](memory.md#热记忆预算与降级规则)。以下保留早期设计由来，当前进度归checkpoint，设备与部署状态归各自owner，不重复执行已完成的P0。

用户要求本轮担任规划师，核查现有架构及记忆，先固定设计供其他 agent 开工，不编写业务代码。系统为 RK3588 IPC（YAM底层）与 Thor（condapi推理）两节点；开发机/训练服务器处于管理与离线数据路径。职责、接线/存储原则、接口闸门、P0–P8实施顺序与交付范围固定于 [架构基线 v1](dagger_architecture.md#2026-09-14-架构基线-v1)，模型语义归 [模型契约](condapi_interface.md)。

用户随后明确四臂各自USB-CAN接口通过USB Hub接IPC，数量为两follower、两leader，第一步锁定各机械臂所接 USB-CAN 下联口与相机序号/视角；不要求机械臂本体S/N。P0身份登记优先于完整部署和运动联调，具体登记归硬件owner。

用户硬件到货说明、既有现场证据、本轮源码核查、待实现要求分开记录。具体物理映射、NVMe挂载、模型身份、单位/action_dt和真机性能仍需实测；本轮不把硬件就绪或历史离线W推理提升为可执行闭环，不触发远端部署或运动。
