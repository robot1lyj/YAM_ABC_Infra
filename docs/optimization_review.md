# 架构与代码优化建议

审核基线：`1c04c83`，2026-09-08。以下区分本轮已修复与剩余建议；未实测的项不称为性能瓶颈。本轮新增数据采集和双按钮仲裁。

## 结论与顺序

现有分层适合第一版：控制、网络、相机、编码已分开；epoch 和有界队列值得保留。建议先补事件一致性、故障证据和模型契约，再到 RK3588 测量决定性能优化。暂不迁移 ROS2、拆成多个服务或强推 C++。

## P1：真机前优先补

### 1. 统一“保持”事件优先级与队列清理

本轮已实现：物理第二按钮与网页保持统一清空待处理命令；第二按钮按住时持续覆盖启动/切换指令，释放不自动恢复。左右 Leader 顶部独立检测上升沿，同一 tick 合并为一个事件，整站250ms去抖。测试包含保持期间排队启动、释放、左右独立按键与多段采集。

### 2. 把设备故障和清理结果落盘

源码：[Runtime 的异常与 finally](../yam_abc_reproduce/hil/run.py)、[Recorder](../yam_abc_reproduce/hil/recording.py)、[StationIO.close](../yam_abc_reproduce/hil/station.py)。

本轮已将 Runtime 终止 status（含故障/保持错误）保存到会话 metadata；已结束片段不会追写未来状态。manifest 的 error 仍主要反映录制器自身错误。`StationIO.close()` 返回清理错误列表，入口也未持久保存。

建议增加终止事件：异常类型、阶段、最后 tick、各臂提交结果、保持/关闭尝试及结果。异常事件通过独立的小型日志或明确的 recorder 终止接口落盘，避免录制大队列满时连故障原因也丢失。

验收：注入右臂提交失败、磁盘失败、SDK停止更新；重新打开输出目录能确定故障原因和最后完整帧。设备保护优先于落盘，不能等待磁盘后才保持。

### 3. 绑定模型语义，不只检查数组形状

源码：[LocalEdgePolicy](../yam_abc_reproduce/hil/run.py)、[动作检查](../yam_abc_reproduce/hil/core.py)；规范：[condapi接口](condapi_interface.md)。

当前会保存服务元数据并检查50×14/有限值/夹爪范围，但未自动核对 checkpoint、norm、单位、绝对动作语义、action_dt 和观测/动作索引约定。形状正确仍可能接错模型。

建议引入轻量、版本化的本地契约文件，并与服务可提供的字段比较。服务不提供的字段保留为人工核验项，不伪造通过；至少把明确错误的单位、模型维度、归一化身份挡在策略执行前。

验收：正确模型通过；相同形状但错单位或错norm的假服务不能进入POLICY。无需为此改WebSocket协议或建立复杂注册中心。

## P2：先测量，再优化

### 4. 增加有界的分阶段耗时统计

当前主要有 deadline miss 和瞬时状态，难以判断慢在采集、状态读取、仲裁、SDK提交还是编码。
建议用固定容量窗口统计 p50/p95/p99、最大值和过期/丢弃计数，按低频更新界面；时钟用本机单调时间。先采集真实 RK3588 数据，不预设某个环节必须低于1ms。

验收：统计自身占用小、窗口容量固定，持续运行不增长内存；可区分网络慢与本地控制慢。

### 5. 优化编码前先保留逐帧数据对应

源码：[Recorder._run](../yam_abc_reproduce/hil/recording.py)。当前三路在同一写盘线程顺序编码，固定软件 `libx264`，相同相机帧可按控制tick重复编码，JSON每行flush。

只有实测编码或磁盘成为瓶颈，再考虑按 frame_id 复用视频索引、配置编码器、减少非必要flush或拆编码进程。不能简单跳帧后继续假定“控制第N步=视频第N帧”。

验收：视频索引、状态/动作对齐和专家导出保持正确，队列占用下降；不以更低画质或丢专家标签冒充优化成功。

### 6. 精简原型与模块之间的私有访问

当前 Runtime 使用 `hil/observation.py`，独立 `hil/snapshots.py` 仍由旧测试覆盖；Session 直接写 Arbiter 的 `_last_request_at` 和 `pending`。

建议合并帧配对实现，提供 `request_submitted`、`request_cancelled` 等明确方法，减少调度状态被多处维护。硬件私有SDK字段继续集中在 `yam_adapter.py`，并写明依赖的SDK版本。

验收：迟到响应、接管、普通基准和异步路径的回归仍通过；不引入抽象层级超过实际需求的插件框架。

### 7. 专家导出避免按片段反复解码整段视频

源码：[export._video_subset](../yam_abc_reproduce/hil/export.py)。每个人工片段、每个相机都会从源视频开头解码到目标索引；干预片段多、episode长时会放大工作量。

建议每个源视频顺序解码一次，按有序片段索引分发，或在确认关键帧语义后做seek。离线转换不在控制路径，优先级低于运行稳定性。

验收：输出片段/帧数与当前实现一致，用长episode多片段样本比较时间和内存。

## 暂不做

- 不以三台 D405 同时曝光为前提，不因软件相位差立即换硬件。
- 不在没有CPU/复制开销证据时上共享内存多进程；不提前迁移ROS2。
- 不把 RTC、时间集成和块间融合一起加入，避免同时改变多个模型执行变量。
- 不靠增大所有超时来隐藏设备故障，也不把所有小偏差都升级成急停。

事件优先级已在本轮修复。下一轮补齐设备关闭结果和终止原因的持久记录，再随实际 Thor 服务联调完善模型契约，保留现有控制架构。
