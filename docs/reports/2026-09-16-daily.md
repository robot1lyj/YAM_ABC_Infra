# 项目工作汇报｜2026-09-16

## 项目名称

YAM 双臂机器人设备与数据平台建设。设备与采集平台运行在 RK3588 IPC，负责四臂、三台 D405、遥操作和原始记录；Thor 负责模型推理；数据集平台负责数据整理、审核和导出。

## 已完成工作

1. **收敛推理轨迹方案和控制边界。** 根据现场动作反馈，撤回纯 100Hz 线性插值和多块动作融合，保留最新动作块 `raw`、可关闭的短接缝 `smooth`，以及独立的 100Hz 二阶轨迹路径；页面可以显示当前轨迹模式并在参数变化时清空旧缓冲、更新控制周期。新增策略选择、动作下发、SDK 调用和反馈时间记录，便于后续定位动作抖动和延迟来源。相关本地回归为 338 项通过、3 项跳过。

2. **完善回位、急停和故障恢复的产品流程。** 明确固定零位只作用于两台 Follower，Leader 保持手动重力补偿，不接受位置回位目标；修复回位轨迹在电机死区下无法累积的问题，并改为由反馈治理、超差和停滞条件共同决定是否停止。页面补充故障后的 HOLD、维护可用性和具体阻断原因；这些改动已完成离线专项验证，真实回位仍需继续现场复测。

3. **完成录制与控制隔离的第一版实现和实测。** 将录制、NVMe 临时暂存、分段清单和编码器整理为独立 owner，控制进程保留 4–7 号 CPU；录制端使用文件暂存承受编码突发，停止时按真实写入进展排空。四臂断开条件下，三台 D405 连续 90 秒录制提交 2692 帧，HDF5 与三路 MP4 均完整回读，保存约 2.4 秒，NVMe 临时文件最终排空。跨进程 90 帧突发和录制进程异常进入 HOLD 的离线验证也已完成。

4. **完成 IPC 侧真实 Thor 协议探针。** 100000 检查点已在 Thor 以 `ws://192.168.250.1:8000` 启动常驻普通 WebSocket 服务，容器设置为自动重启；健康检查通过。Thor 本机真实三相机、14D 状态和任务文本请求在 120W 下单次推理/往返约 174.71/177.07 ms，MAXN 下约 106.10/107.16 ms。IPC 使用三路相机图像和 14D 状态完成无电机探针，返回有限的 `(50, 14)` 动作，证明网络、封包、形状和有限值路径可用。

5. **完成模型与训练环境的配套工作。** 发现 100000 模型近期动作与任务抓取目标仍有偏差，完成夹爪输出、轨迹接缝和物体分布的只读诊断，形成先固定控制、再做小规模现场微调的方案。Evo-1 基座 VLM 完成下载、服务器交接和哈希核对；FlashAttention 2.8.3 环境修复后，RTX 4090 上实际启用 `flash_attention_2`，单注意力核前向约比 math-only SDPA 快 14.18 倍。Pi0.5 training-time RTC 入口、随机约 10 小时子集训练和监控/断点交接已经启动，尚未形成可部署的新模型。

6. **完成当天故障和数据边界记录。** 记录了推理短测中的录制队列达到 300 项、相机启动期间 SDK 状态过期、USB-CAN 无应答以及 IPC 重启后 NVMe 间歇未枚举等现象，并保留了故障时序、日志和恢复范围。没有把一次重启恢复、离线轨迹结果或无电机探针写成四臂闭环通过。

## 当前问题

1. **IPC 存储和设备链路不稳定。** 多次启动出现 `fe150000.pcie` 链路建立失败，NVMe 未枚举、`/data` 未挂载，导致设备和网页服务无法启动；USB-CAN 也出现左侧电机无应答，重枚举或重启后曾恢复，但尚未定位到 NVMe、USB Hub、适配器、供电或控制器的具体根因。存储和四路 CAN 未稳定前，不应继续运动测试。

2. **推理轨迹效果仍未确定。** 纯线性插值已因异常动作撤回；`smooth/10步` 的接缝相对新动作块最大关节偏差 P95 约 0.412 rad，100Hz 二阶路径仍存在相对输入目标的滞后。不同模式尚未在同一任务、同一初始状态下完成公平对照，不能据局部反向计数或短时体感确定最终默认方案。

3. **推理录制吞吐仍是现场阻断。** 两次真机推理录制分别在 1325 和 1370 帧附近触发 300 项外层队列上限，episode 按失败语义中止；数据已提交的片段仍可回读，但采集实际写出约 23–24 帧/秒，无法满足长期 30Hz 录制要求。NVMe spool 和独立录制进程只完成短时/离线验证，尚未完成运动中长时验收。

4. **Thor 已在线，但闭环尚未完成。** 100000 服务和 IPC 无电机协议探针均通过，仍未完成有电机的动作单位、`action_dt`、动作执行时序和任务成功率验证；夹爪近期预测与实际抓取目标存在偏差。有效 prompt 超过 80 token 时还需重新准备同一检查点的 200 桶引擎，不能截断有效文本。

5. **数据集平台交付和训练结果仍待完成。** 数据集平台 8767 的局域网部署、跨平台浏览器验收及真实推理/示范数据的导入审核导出闭环尚未完成；RTC 子集训练尚未完成首个可恢复检查点和模型效果评估，Evo 尚未跑完整 policy 或正式 YAM 训练。

## 下一步计划

1. 优先稳定 IPC：现场检查 NVMe、PCIe、供电和 USB-CAN/Hub 物理链路，确认 `/data` 可持续挂载、四路 CAN 可正常拉起，再恢复服务并重新核验相机和四臂 HOLD。
2. 在有人监护下完成 Follower 回位复测、单组再双组低幅遥操作，以及真实急停、暂停和恢复；所有测试保留逐臂状态龄、CAN 统计、控制周期和轨迹下发记录。
3. 继续完善 NVMe spool 和录制进程隔离，先完成无运动长时队列斜率，再进行运动中录制与不录制对照，确认 30Hz 写入、温升、磁盘空间和故障收尾。
4. 在同一任务和初始条件下对照 `raw`、少量 `smooth` 和 100Hz 二阶轨迹，优先解决动作块不一致、夹爪选择和实际墙钟调度问题，再决定默认策略。
5. 继续使用 Thor 100000 服务，先完成真实 RK3588→Thor 的冻结观测回放和动作合同核验，再进行有人照看的短时纯推理；RTC 训练需先完成首个保存、恢复和离线评估。
6. 实现数据集平台 8767 的局域网访问，贯通真实数据的导入、分类、审核、导出和回读，并补齐跨操作系统浏览器证据。
