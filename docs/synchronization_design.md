# 同步、时间轴与性能合同

本文以当前源码/配置为准；历史测量见 [验收](acceptance.md) 和 [整理前快照](archive/synchronization_design_20260922.md)。软件时间对齐不是曝光同步，也不是硬实时保证。

## 四种不同的时间

| 时间 | 用途 | 边界 |
|---|---|---|
| 相机设备时间、帧号 | 保留传感器来源信息 | 未建立三机统一曝光时钟 |
| IPC 主机接收时间 | 三路软件配对、估计观测年龄 | 不是曝光时刻，预热不消除每帧传输延迟 |
| IPC monotonic / policy tick | 请求关联、动作期限、30 Hz 时间轴 | 不能与 Thor monotonic 直接相减 |
| 录制 frame_index / timestamp | 删除等待后连续的训练帧序号及时间 | 不代表物理时间连续或相机同时曝光 |

三台 D405 不使用外部硬件同步。当前相机历史配对与关节历史插值得到 observation_state；控制反馈 measured_state 使用当前 SDK 读数。插值状态不是重新测量，`sdk_state_age_s` 也不是每个电机 CAN 包年龄。

## 进程与执行频率

- 相机各自采集；观测配对只取可用历史，不让控制等待新图。
- Thor 通信和动作规划使用独立子进程，最多一个推理请求在途，不积压旧 observation。
- Runtime 30 Hz 选择并提交目标；SDK 底层继续位置/力矩控制。上层 30 Hz 不等于电机内部频率。
- 默认 `policy_trajectory_hz=0`：不经过本站 100 Hz 二阶写入。可选二阶保留；失败的 100 Hz 纯线性实现已移除。
- 编码/录制/预览在后台；独立进程和 CPU 亲和性不隔离共享内存带宽、USB、磁盘或全部调度竞争。

不把 OpenArm-vr 的 200 Hz 控制频率直接套作 YAM SDK 的已测事实。默认策略目标不再施加基于“实测位置±速度×dt”的应用层追逐包络；SDK 硬限位与夹爪范围仍有效。

## 三种动作时间合同

| 模式 | 新块如何消费 | 与旧块关系 |
|---|---|---|
| sync_hold | 完整50步，从0开始；执行完保持再请求 | 不预取、不融合；完整块期限从回复开始计算 |
| tda_smooth | 按请求期间实际消费步数对齐，沿 OpenArm-vr 队列规则处理 | 对队列重叠段线性混合，含夹爪；不只是固定4步过渡 |
| rtc | 明确 `observation_policy_tick=k`，发送已承诺前d步 | 前缀不改，新块从k+d接管；迟到不能挪到更晚执行 |

三者不是同一种“跳过网络延迟前缀”的算法。RTC 不经过 TDA、普通夹爪 trick 或二阶轨迹；普通同步不能被异步的1.5秒观测时效裁掉50步末尾。代码共同检查 epoch、有限值、形状和适用期限。

## 预取与 d

TDA 常规重规划间隔由 `replan_period` 配置；缓冲接近耗尽时，结合有效回复的观测到可用延迟 p95、初始估计和余量提前请求。旧请求未返回时不再排新请求。

RTC 的 d 是承诺前缀长度，不是融合长度。30 Hz 下预算估算为
`ceil(观测到动作可用耗时 / (1/30秒))`，若有明确余量再加入；仍须看控制 tick 离散化、迟到率和服务声明上限。当前 YAML 预设9，仅是配置，不是当前 Thor 延迟实测。网络往返与帧龄独立 p95 相加不等于联合 p95；不能凭历史195 ms推断当前可用 d。

超时/耗尽保持，暂停/接管/重置使旧 epoch 失效，服务恢复不自动恢复运动。

## 记录与资源验收

数据通路使用有界 RAM、磁盘 spool、分段 MP4/HDF5，允许结束后继续封装；磁盘暂存本身持续慢于输入仍会失败。新恢复能力不保证断电时尚在 RAM 的帧完整。

评估分别报告：控制工作耗时和 deadline miss、SDK反馈年龄、目标/反馈误差、相机帧龄/偏差、请求往返/端到端延迟、录制队列/磁盘吞吐。不能把目标平滑程度当抓取效果，或把各级 p95 直接相加称为总延迟。

先离线模拟延迟与故障，再无电机 Thor 探针，再获准运动对照与长时录制。当前离线/现场证据入口见 [验收边界](acceptance.md)，配置解释见 [运行手册](hil_quickstart.md#实用同步与性能默认值)。
